# Авторский голос

Локальное приложение для сборки инструкций авторского голоса. Вы добавляете свои тексты и ориентиры, отдельно анализируете каждый источник через OpenRouter, выбираете приемы, редактируете правила и получаете два документа: подробную инструкцию и компактный содержательный промпт. Оба документа можно править, сохранять как версию и экспортировать без обязательной проверки.

Приложение работает на вашем компьютере без регистрации. Это конструктор инструкций для другого ИИ; редактора произведений и аудиофункций в нём нет.

## Быстрый запуск в Windows

1. Запустите Docker Desktop.
2. Откройте PowerShell в `C:\ai_voicers`.
3. Выполните:

   ```powershell
   docker compose up -d --build
   ```

4. Откройте [http://127.0.0.1:3333](http://127.0.0.1:3333).

Первый запуск собирает образ, создает БД и применяет миграции. Сервис публикует порт только на `127.0.0.1`; PostgreSQL наружу не публикуется. Готовность приложения можно посмотреть по адресу [http://127.0.0.1:3333/api/health/ready](http://127.0.0.1:3333/api/health/ready).

## Первые действия

1. Откройте **Настройки → Провайдер** и сохраните API-ключ OpenRouter. Ключ вводится только в приложении; в ответе API видна лишь его маска. Кнопка **Проверить подключение** проверяет ключ без генерации текста.
2. Выберите модель из каталога или введите точный `provider/model` вручную. Если каталог недоступен, ручной ввод продолжает работать. Уровень рассуждения задается для новых циклов.
3. Создайте проект. В нём появятся пять пустых слотов; для начала достаточно одного текста. У источника укажите **Мой голос**, **Ориентир** или **Не указано**.
4. Запустите анализ каждого нужного текста. Во вкладке **Приемы** выберите конкретные карточки. Добавьте пожелания и ограничения, если они нужны.
5. Нажмите **Сформировать правила**. Во вкладке **Правила** отметьте нужные предложения, поправьте их или добавьте свое правило. Новые предложения не выбираются автоматически.
6. Соберите подробную инструкцию. Проверьте предложение и примените его. Затем создайте промпт-версию из точного текста подробной инструкции. Оба текста можно править и экспортировать в Markdown или TXT.

Анализ, формирование правил, сборка, промпт, проверка и проба обращаются к модели только по отдельным командам. Они могут расходовать средства OpenRouter. Сохранение, фильтры, переключение вкладок, версии и экспорт генерацию не запускают.

**Важная особенность текущей версии:** у правила есть колонка «Делай так / Не делай так» и свободная формулировка. Приложение передает модели оба поля, но пока не умеет надежно находить смысловые противоречия между ними. Например, «Чередуй короткие и длинные фразы» в колонке «Не делай так» неоднозначно. Перед сборкой проверьте, что направление и текст выражают одно намерение. Подробные примеры — в [руководстве пользователя](docs/USER-GUIDE.md#как-формулировать-правила).

## Обновление и остановка

Для обновления выполните ту же команду `docker compose up -d --build`. Compose использует отдельные тома `database`, `keys`, `backups`; обычная пересборка их сохраняет. Остановка: `docker compose down` **без** `-v`. Ключ шифрования из тома `keys` нужен вместе с дампом БД для восстановления зашифрованного ключа OpenRouter. Перед миграцией существующей БД создается дамп, а инструкция безопасной проверки восстановления приведена в [операционном руководстве](docs/OPERATIONS.md#резервные-копии-и-проверка-восстановления).

Исходники интерфейса и API находятся в `src/app`, worker — в `src/worker.ts`, схема БД — в `prisma/schema.prisma`. Для разработки предусмотрены `npm ci`, `npm run db:generate`, `npm run typecheck`, `npm run lint`, `npm test` и `npm run build`; рабочий запуск выполняется через Docker. Приложение использует Next.js, React, TypeScript, PostgreSQL, Prisma и pg-boss. Шрифты Oswald Regular и Huninn поставляются локально в `public/fonts` с лицензиями рядом.
