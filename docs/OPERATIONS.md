# Запуск, обновление и сохранность данных

Основная среда проекта — Windows с Docker Desktop. Команды ниже приведены для PowerShell, открытого в `C:\ai_voicers`. Пользовательский процесс описан в [руководстве](USER-GUIDE.md).

## Что запускает Compose

| Сервис | Задача | Хранение |
| --- | --- | --- |
| `db` | PostgreSQL 17 | Том `database`; порт БД на хост не опубликован |
| `backup` | Создает дамп перед миграцией уже существующей БД | Том `backups` |
| `migrate` | Выполняет `prisma migrate deploy` | Подключается к `db`; использует том `keys` |
| `web` | Интерфейс и локальный HTTP API | Том `keys`; порт 3333 на `127.0.0.1` |
| `worker` | Выполняет задания ИИ из очереди | Том `keys`; задания и учет токенов в БД |

`backup` и `migrate` — одноразовые этапы запуска. Их состояние `Exited` после успешного завершения нормально. Рабочие сервисы — `db`, `web` и `worker`.

Порядок: здоровая БД → дамп существующих данных → миграция → web и worker. На самом первом запуске, когда таблицы `Project` еще нет, скрипт резервного копирования не создает дамп. Именованные тома создаются Compose и переживают пересборку контейнеров.

## Первый запуск и обновление

```powershell
docker compose up -d --build
docker compose ps
```

Откройте [http://127.0.0.1:3333](http://127.0.0.1:3333). `APP_PORT` и `APP_BIND` можно задать в локальном `.env` по образцу [`.env.example`](../.env.example). По умолчанию используется `127.0.0.1:3333`. Публикация на другом адресе меняет границу доступа; приложение рассчитано на локальный loopback и проверяет `Host`/`Origin`.

Обновление выполняется той же командой. Compose пересоздает контейнеры, но сохраняет тома `database`, `keys`, `backups`. Миграции применяются к текущей БД после создания дампа. Для обычной остановки:

```powershell
docker compose down
```

**Не добавляйте `-v`** к `down` при обновлении: этот флаг удаляет тома с данными. `docker compose build web` и `docker compose up -d --no-deps web` подходят для замены только веб-контейнера, когда схема БД и worker не менялись; для обычного обновления используйте полную команду выше.

## Проверка состояния

```powershell
docker compose ps
docker compose logs --tail=100 web worker
```

`GET /api/health/live` показывает, отвечает ли веб-процесс. `GET /api/health/ready` возвращает `ready` только при доступной БД и недавнем сигнале worker; отсутствие worker дает HTTP 503. Healthcheck контейнера web использует `ready`. Пример:

```powershell
Invoke-RestMethod http://127.0.0.1:3333/api/health/ready
```

Не публикуйте журналы, дампы, файл master key и тексты референсов в открытых отчетах. В интерфейсе стадия задания и прошедшее время показываются без искусственного процента. Очередь и результаты хранятся в PostgreSQL, поэтому перезапуск web не должен стирать задания. Worker при старте возвращает прерванные задания из состояния `running` в очередь; исходный запрос провайдеру при этом мог уже состояться, поэтому повтор способен повлечь дополнительный расход.

## Резервные копии и проверка восстановления

При запуске обновления `backup` делает дамп формата PostgreSQL custom (`pg_dump -Fc`) с именем `pre-update-YYYYMMDDTHHMMSSZ.dump`, если уже существует таблица проектов. Файлы находятся в томе `backups`; автоматического удаления старых копий нет. Копии внутри Docker не защищают от потери самого диска или всех томов — при необходимости храните отдельную копию вне Docker.

Удаление проекта в приложении очищает его данные из **рабочей БД**, но не переписывает старые дампы: они остаются снимками состояния на момент создания и могут содержать удаленный проект. Это важно учитывать при хранении и отдельном удалении резервных копий.

Посмотреть список дампов:

```powershell
docker compose run --rm backup sh -c "ls -lh /data/backups"
```

Проверить последний дамп без замены рабочей БД:

```powershell
docker compose run --rm backup sh /scripts/verify-backup.sh
```

Скрипт создает временную БД, восстанавливает в нее последний дамп, проверяет наличие проектов, версий и записей ключей, затем удаляет только временную БД. Он **не сравнивает каждый текст и не восстанавливает рабочую БД**. Скрипт рассчитан на непустую установку с хотя бы одним проектом, версией и записью ключа; на новой установке такая проверка закономерно не пройдет.

API-ключ OpenRouter зашифрован в БД. Master key — отдельный 32-байтовый файл `/data/keys/master.key` в томе `keys`. Для реального восстановления зашифрованного ключа нужны **совместимый дамп БД и исходный том `keys` или сохраненная копия его файла**. Потерянный master key не заменяется молча; старый шифротекст не расшифруется. Если исходный ключ восстановить нельзя, удалите старую запись ключа OpenRouter через настройки и затем введите API-ключ заново: прямая замена при существующем шифротексте и отсутствующем master key вернет ошибку.

В проекте нет автоматического сценария восстановления поверх действующей БД. Перед такой операцией остановите web и worker, сохраните отдельные копии текущих томов и проверьте дамп в отдельной БД. Затем возвращайте БД и соответствующий master key как согласованную пару. Не запускайте `pg_restore --clean` на рабочей БД без отдельной проверенной процедуры: это удаляющее действие. После восстановления применяйте миграции из совместимой версии кода.

## OpenRouter и расходы

Ключ вводится на странице **Настройки** и шифруется AES-256-GCM на сервере. В браузерном ответе остается только маска. **Проверить подключение** использует endpoint проверки ключа OpenRouter, без генерации. **Обновить каталог** загружает список моделей, тоже без генерации.

Платные вызовы возможны при анализе, формировании правил, сборке инструкции, создании промпта, проверке и текстовой пробе. Каждый запуск является отдельным заданием. Повтор после сетевой ошибки может повлечь дополнительный расход, даже если приложение не получило готовый результат. Сводка токенов показывает данные, которые фактически вернул провайдер; неполные сведения не подменяются нулём. Выбранная модель и рабочие инструкции фиксируются в цикле после первого анализа, запуска формирования правил или полной сборки методом 2.

Если анализ длится долго, раскройте **Время этапов** у завершенного задания во вкладке **История**. Для новых заданий показываются миллисекунды локальной подготовки, ожидания заголовков и потока OpenRouter, проверки и записи; для ошибок показываются только этапы, до которых дошло задание. Число токенов рассуждения появляется только при наличии этого поля в ответе провайдера. Диагностика не содержит исходник или ключ. Для DeepSeek Flash с высоким уровнем рассуждения по умолчанию новый цикл предлагает `low` с сохранением рассуждения, но уже зафиксированный цикл сохраняет прежнюю настройку. На синтетическом тексте 2550 символов `auto` занял 131 с и 9779 токенов рассуждения, `low` занял 100 с и 11514 токенов рассуждения. Эти два вызова не доказывают стабильного ускорения. Анализ теперь предпочитает endpoint той же модели с более высокой пропускной способностью; фактический провайдер и цена могут измениться.

`AI_ADAPTER=test` включает явно обозначенный тестовый адаптер с предсказуемыми ответами. Не используйте его результаты как подтверждение работы OpenRouter. Для повседневной работы переменная должна оставаться неустановленной или иметь значение `openrouter`.

## Изолированный тестовый экземпляр

[`compose.method-test.yaml`](../compose.method-test.yaml) запускает отдельный проект Compose на `127.0.0.1:3334`. Его БД и каталог ключей находятся в tmpfs; рабочие тома `database`, `keys`, `backups` не подключаются. Адаптер принудительно установлен в `test`.

```powershell
docker compose build web
docker compose -p ai_voicers_method_test -f compose.method-test.yaml up -d
docker compose -p ai_voicers_method_test -f compose.method-test.yaml exec -T web node scripts/method-smoke.mjs
docker compose -p ai_voicers_method_test -f compose.method-test.yaml exec -T web node scripts/project-delete-smoke.mjs
node scripts/method-browser.mjs
docker compose -p ai_voicers_method_test -f compose.method-test.yaml down
```

`method-smoke.mjs` создает синтетические тестовые проекты в изолированной БД; браузерный сценарий использует их. `project-delete-smoke.mjs` удаляет только свой синтетический проект и проверяет каскадное удаление при сохранении другого проекта. Для браузерного сценария нужны локальные зависимости из `npm ci` и установленный браузер Playwright. Запускайте его после API-сценария. Остановка тестового Compose удаляет временную БД вместе с контейнером, потому что она размещена в tmpfs.

## Типичные ситуации

| Симптом | Что проверить |
| --- | --- |
| Страница на 3333 не открывается | Работает ли Docker Desktop; `docker compose ps`; занятость порта; состояние `web` и `migrate` в логах. |
| `ready` возвращает 503 | Состояние `db` и `worker`, журналы worker. `/live` при этом может отвечать. |
| «Ключ не настроен» или ключ отклонен | Маску и **Проверить подключение** в настройках; при утрате тома `keys` восстановить исходный master key либо ввести ключ OpenRouter заново. |
| `MODEL_UNAVAILABLE` или HTTP 404 от OpenRouter | Во вкладке **История** проверьте точный model ID без генерации. Обновите каталог и создайте новый цикл с доступной моделью. Сайт OpenRouter может показывать страницу модели, которая сейчас отсутствует в API; приложение не подменяет её другой моделью автоматически. |
| Каталог моделей недоступен | Введите точный `provider/model` вручную. Проверка каталога не нужна для сохранения ID. |
| «Контекст выбранной модели недостаточен» | Посмотрите model ID и предел **текущего цикла**. Оценка приблизительна; текст остается сохраненным. Для другой модели создайте новый цикл. |
| Анализ завершился, а результата не видно | Для метода 2 смотрите **Приемы**, для старого цикла — блок **Разборы** в **Референсах**. Проверьте выбранный цикл, состояние задания и не изменялся ли текст после анализа. |
| «Последняя группа предложений основана на прежнем выборе» | После генерации изменились входные приемы, настройки, роль источника, пожелания или ограничения. Правила остаются; при необходимости нажмите **Предложить новые правила**. |
| Правки не сохранились | Дождитесь статуса **Сохранено** или нажмите **Повторить сохранение**. При конфликте двух вкладок скопируйте введенный текст перед обновлением страницы. |
| Промпт помечен устаревшим | Полная инструкция изменилась после создания промпта либо промпт введен вручную без связи с ней. Текст можно экспортировать; новую связанную версию создавайте отдельной кнопкой. |

Точные коды и ограничения HTTP API приведены в [справочнике](API.md), а внутренний путь задания — в [описании архитектуры](ARCHITECTURE.md).
