# Руководство пользователя

Это описание интерфейса текущей версии. Быстрый запуск — в [README](../README.md), обслуживание Docker и данных — в [операционном руководстве](OPERATIONS.md).

## Основные понятия

| Понятие | Что означает |
| --- | --- |
| Проект | Общая рабочая область с названием и несколькими циклами. Архивирование скрывает проект из обычного списка; удаление удаляет его историю. |
| Цикл | Работа с одной моделью и одним снимком рабочих инструкций. После первого анализа, формирования правил или полной сборки методом 2 новые настройки требуют нового цикла. |
| Референс | Отдельный исходный текст. У него есть роль, название, необязательные поля автора, фокуса и комментария, а также история редакций текста. |
| Разбор | Ответ модели для одной редакции одного референса. Содержит описание звучания, карточки приемов и подтверждающие фрагменты. |
| Прием | Конкретная карточка разбора. Чекбокс выбирает именно ее; снятие выбора не создает запрет. |
| Правило | Редактируемое предложение или ваша собственная формулировка. Только отмеченные правила участвуют в сборке нового метода. |
| Предложение документа | Новый текст от модели. Его можно сравнить с текущим документом и применить отдельной кнопкой. |
| Версия | Именованный снимок цикла, включая документы, источники, выбор и правила. Продолжение версии создает отдельный рабочий цикл. |

## 1. Настройте OpenRouter

Откройте **Настройки**. В блоке **Провайдер** введите API-ключ и нажмите **Сохранить ключ**. После сохранения видна только маска с последними четырьмя символами. **Удалить** удаляет сохраненную запись ключа. **Проверить подключение** обращается к сервису проверки ключа OpenRouter и не запускает генерацию текста. Проверка подключения не подтверждает, что выбранная модель доступна для конкретного запроса.

В блоке **Модель новых циклов** можно ввести точный model ID в виде `provider/model`. Поле сохраняется при потере фокуса. Кнопка **Обновить каталог** загружает список моделей; после этого доступны поиск и выбор. Недоступность каталога не отключает ручной ввод. Выберите также уровень рассуждения: по умолчанию модели, низкий, высокий или максимальный. Доступность конкретного уровня зависит от модели и OpenRouter. Настройки используются при создании следующих циклов; уже начатый цикл хранит собственные значения.

Ручное обновление каталога запрашивает свежий список у OpenRouter с учетом сохраненного ключа. Во вкладке **История** открытого проекта можно проверить введенный model ID без генерации текста и получить подсказки из каталога для нового цикла. Если проверка сообщает «недоступна», выбранный ID сейчас не работает с настроенным ключом и условиями OpenRouter; выберите другую доступную модель. Переход на неё создаёт новый цикл, потому что модель старого зафиксирована. При первом запуске анализа новый цикл тоже проверяет model ID до фиксации и очереди: подтвержденный 404 не отправляет исходный текст на генерацию.

Для `~deepseek/deepseek-flash-latest` и `deepseek/deepseek-v4.1-flash` приложение предлагает **Низкий** уровень с сохранением рассуждения при выборе модели для нового цикла. У этих моделей OpenRouter сообщает высокий уровень по умолчанию. Контрольный вызов с **Низким** уровнем тоже потратил более 11 тысяч токенов рассуждения, поэтому изменение одного этого параметра не гарантирует быстрого анализа. Запросы анализа предпочитают более быстрые endpoint той же модели, если они доступны. Режим **Без рассуждения** остается отдельным выбором, но для полноценного разбора его выбирать не требуется. Если текущий цикл уже зафиксирован, во вкладке **История** создайте новый цикл: исходники скопируются, прежние разборы не переносятся.

В блоке **Рабочие инструкции** находятся шесть отдельных шаблонов: анализ, кандидаты в правила, сборка полной инструкции, промпт-версия, проверка и текстовая проба. **Сохранить новую редакцию** создает неизменяемую редакцию и выбирает ее для новых циклов. Это служебные инструкции для модели; две итоговые инструкции редактируются в проекте. Кнопки с `{{переменными}}` вставляют разрешенные переменные в соответствующий шаблон.

Светлая и темная темы переключаются там же. Ключ в файл `.env` помещать не нужно.

## 2. Создайте проект и подготовьте источники

На главной странице введите название и model ID, выберите уровень рассуждения, затем нажмите **Создать проект**. Для DeepSeek Flash предлагается **Низкий** уровень с сохранением рассуждения; его можно изменить перед созданием. Новый проект содержит пять пустых слотов «Отрывок 1» и далее. Пустые слоты не нужно заполнять: одного референса достаточно, а новые можно добавить кнопкой **+ Добавить**.

Во вкладке **Референсы** откройте слот. Выберите роль:

- **Мой голос** — текст, в котором вы уже звучите естественно.
- **Ориентир** — другой текст, отдельные приемы которого хотите осознанно использовать.
- **Не указано** — роль пока не определена; такой референс тоже можно анализировать и выбирать из него приемы.

Вставьте текст и дождитесь надписи **Сохранено**. Название, автор, фокус, комментарий и текст сохраняются автоматически после паузы или выхода из поля. Кнопка **Анализировать** доступна для непустого сохраненного текста как в раскрытой карточке, так и в ее свернутой строке. Треугольник раскрывает и закрывает карточку. В раскрытой карточке можно выбрать краткий, подробный или углубленный режим; выбранная глубина сохраняется при сворачивании карточки. Это три варианта запроса к модели, а не переключатели уже готового разбора.

Каждый анализ получает только текущий текст данного референса и его глубину. Другие референсы в этот запрос не подмешиваются. Автор, комментарий и название не входят в текст запроса на анализ. Результат сохраняется отдельно; замена исходного текста не стирает старый разбор, но делает его устаревшим для новой редакции. Для актуального выбора после такой правки запустите анализ снова. **Дублировать** создает еще один референс с текущим текстом и ролью, без копии разбора. **Убрать из набора** архивирует референс; его прежнее происхождение в уже созданных правилах остается.

Текст референса ограничен 200 000 символов, а размер HTTP-запроса — 2 MiB. В приложении нет прежнего жесткого предела 30 000 символов. Если у модели текущего цикла указан предел контекста, сервер делает приблизительную проверку с запасом. Он не обрезает текст и не переключает модель сам. При неизвестном пределе точность такой проверки ограничена.

## 3. Следите за заданием и разборами

После запуска появляется плашка **Задание ИИ**. Она показывает фактический этап, время, номер повторной попытки и количество уже полученных символов, если модель их прислала. Движущаяся полоска означает, что задание активно; она не изображает процент выполнения. Можно запросить отмену. При ошибке анализа исходный текст остается на месте, а кнопка **Повторить анализ** запускает новый запрос. Сведения обо всех заданиях есть во вкладке **История**.

Для новых завершенных заданий анализа в **Истории** можно раскрыть **Время этапов**: подготовка, запрос к провайдеру, ожидание заголовков, первый фрагмент, поток, проверка и сохранение. Если OpenRouter сообщил число токенов рассуждения, оно указано отдельно. У старых заданий такой разбивки нет; отсутствие числа рассуждения не означает нулевой расход.

Когда анализ завершился, откройте **Приемы**. Доска разделяет «Мой голос», «Ориентиры» и источники без роли. В описании звучания цель и аудитория помечены как предположения модели. В карточке приема есть принцип, категории, эффект, нюансы и фрагменты текста. Фрагмент помечается, если точное совпадение с исходником не подтвердилось. Метка **Форма**, **Тема** или **Форма и тема** помогает решить, переносить ли прием в будущий голос.

Фильтр категории и **Только выбранные** работают локально, без запроса к модели. В базовом режиме достаточно чекбоксов. **Расширенный режим** добавляет состояние приема, его роль, выраженность от 1 до 5, частоту и условие. Значение **Исключен** в выборе приема не превращается автоматически в запрет для итоговой инструкции. Для начала формирования правил нужны выбранные приемы, пожелание или ограничение.

## 4. Добавьте пожелания и сформируйте правила

Под доской находится **Что добавить от себя**. Пожелание может описывать свойство, которого нет в референсах; оно сохраняется как ваше основание. Ограничения задаются отдельно как **Нежелательно** или **Запрет**. Эти поля тоже сохраняются автоматически. Дождитесь статуса сохранения перед переходом к следующему шагу.

Кнопка **Сформировать правила** запускает отдельный запрос к модели. Она получает выбранные приемы с их ролями и настройками, а также пожелания и ограничения. Отдельные поля исходного текста, цитат, имени автора и названия в этот запрос не включаются. При этом выбранные принципы, эффекты и нюансы происходят из ответа модели на анализ, поэтому перед выбором стоит прочитать их: приложение не вычищает упоминания внутри этих формулировок. Модель возвращает кандидатов и пояснения. Новая группа сохраняется как снимок оснований; все ее правила первоначально **не отмечены**.

Во вкладке **Правила** отметьте только нужные предложения. Можно править текст, направление, категорию, условие и силу ограничения. Для «Не делай так» доступны **Нежелательно** и **Запрет**. **+ Свое правило** добавляет правило без обращения к модели, тоже первоначально неотмеченное. У каждого правила можно открыть основания, первоначальный вариант и историю редакций. **Убрать из списка** архивирует карточку, а фильтр позволяет найти ее снова.

**Предложить новые правила** делает еще один запрос и добавляет новую неотмеченную группу. Отмеченные правила и ваши формулировки не заменяются. Если исходный выбор приемов, их настройки, роли источников, пожелания или ограничения изменились, последняя группа помечается как основанная на прежнем выборе. Это предупреждение о происхождении кандидатов; оно не мешает использовать уже выбранные правила.

### Как формулировать правила

Сейчас `direction` («Делай так» или «Не делай так») и свободный текст правила передаются модели одновременно. Приложение не прибавляет к тексту буквальное «не», но и **не разрешает смысловые противоречия автоматически**. Локальное предупреждение находит одинаковые формулировки среди выбранных правил, включая одинаковый текст в противоположных колонках. Оно не понимает обычные русские отрицания и синонимы.

| Желаемый смысл | Более ясная карточка |
| --- | --- |
| Использовать чередование фраз | «Делай так»: «Чередуй короткие и длинные фразы». |
| Избегать напыщенного тона | «Не делай так»: «Не используй претенциозные формулировки»; либо «Делай так»: «Избегай претенциозных формулировок». |
| Не навязывать чередование в каждом абзаце | «Не делай так»: «Не чередуй длину фраз механически в каждом абзаце», с подходящим условием. |

Проверьте, что сама формулировка и выбранная колонка говорят об одном действии. «Чередуй короткие и длинные фразы» в «Не делай так» дает модели два противоречащих сигнала; результат сборки в таком случае непредсказуем. Текущее приложение не предупреждает об этом частном случае и не переписывает фразу. Поэтому особенно внимательно читайте предложение полной инструкции перед применением.

## 5. Создайте и сохраните два документа

**Собрать инструкцию** использует только отмеченные неархивные правила. Модели передаются текст, направление, категория, условие и сила каждого правила. Неотмеченные приемы и кандидаты, референсы, цитаты и исходные пожелания отдельно в сборку не попадают. Для метода 2 требуется хотя бы одно отмеченное правило. При этом пустые документы можно заполнять вручную и сохранять как версию.

Готовый ответ появляется как **Предложение**, рядом с текущим текстом. В предложении можно внести правки и нажать **Применить**; без этого текущая подробная инструкция не меняется. Ее основной текст находится в редакторе **Подробная инструкция**. Нажатие **Создать промпт-версию** отправляет модели точный текущий текст этого редактора, а не старую структуру правил. Промпт тоже сначала появляется как предложение и применяется отдельно.

Оба итоговых редактора сохраняют ручные правки автоматически. У каждого есть **Копировать**, **MD** и **TXT**; экспорт берет точный сохраненный текст и не запускает модель. Если полная инструкция изменилась после создания промпта, интерфейс показывает, что промпт устарел. Вручную написанный промпт без связи с полной инструкцией также может сразу иметь эту пометку. В любом случае текст остается доступен для правки и экспорта.

Рядом с кнопкой **Проверить** выберите подробную инструкцию или промпт-версию. Кнопка запускает необязательную проверку выбранного документа. После завершения в блоке **Результат проверки** показываются найденные противоречия и рекомендации. Если модель не указала замечаний, блок сообщает об этом явно. Замечания не являются запретом на сохранение, экспорт или использование. После правки документа прежняя проверка остается видимой, но помечается устаревшей. **Создать пробу** отправляет выбранный для пробы документ и короткую ситуацию модели; каждая проба запускается отдельно.

## 6. Сохраните версию или начните новый цикл

Во вкладке **История** задайте имя и нажмите **Сохранить версию**. Проверка и проба перед этим не обязательны. Версия хранит состояние на момент сохранения и затем не изменяется. **Продолжить с версии** создает другой рабочий цикл на основе снимка; оригинальная версия остается прежней.

Там же можно создать новый цикл с другой моделью или уровнем рассуждения. В новый цикл копируются текущие неархивные исходники и роли, но анализы, выбранные приемы и итоговые документы из обычного перехода не переносятся. Пока цикл не зафиксирован анализом, формированием правил или полной сборкой методом 2, в нем можно уточнить model ID и взять текущую редакцию рабочих инструкций. После фиксации для новой модели или редакции создавайте новый цикл.

**Архивировать** во вкладке «История» скрывает проект из обычного списка на главной странице; его можно показать и восстановить. Кнопка **Удалить проект** находится в верхней части открытого проекта, рядом с выбором цикла. После подтверждения из рабочей БД удаляются все циклы, исходники, разборы, правила, документы, версии и задания проекта. Глобальные настройки и ключ OpenRouter остаются. Старые резервные копии могут по-прежнему содержать проект.

## Ранее созданные циклы

Циклы метода 1 продолжают работать через вкладки **Референсы → Выбор → Результат**: у них нет отдельного шага «Правила». В рабочей области есть **Начать новый цикл по методу**. Это создает цикл метода 2 с копиями текущих неархивных исходников и их ролей. Старые разборы и документы остаются в старом цикле; новый анализ запускается только вручную.

## Когда обращаться к диагностике

Если задание долго выполняется, смотрите его фактический этап и время последнего фрагмента ответа. Углубленный анализ может ждать значительно дольше краткого. Ошибки ключа, модели, сети, структуры ответа и контекста описаны в [операционном руководстве](OPERATIONS.md#типичные-ситуации). Для разработчика доступны точные коды ошибок и состояния заданий в [API](API.md).
